## Summary of MVP

Climbr is a gamified pomodoro timer that transforms the abstract passage of time into a tangible, high-stakes digital struggle. Utilizing the Myth of Sisyphus as a visual metaphor, the app correlates focus time with vertical distance climbed. Unlike "cozy" competitors, Climbr  enforces focus through "Roguelike" mechanics: leaving the app results in immediate loss of progress (the boulder rolls back), creating a  psychological "wall" that prevents digital distraction.

## Core Mechanics

### The Climb (Focus State)

- Time-to-Distance Mapping: The user sets a focus duration (e.g., 25 minutes). Every minute of successful focus corresponds to 1 meter (or unit) climbed up an infinite hill.
- Visual Feedback: As the timer counts down, the Sisyphus character is animated pushing the boulder uphill. The background/environment may shift subtly to indicate altitude gain.
- No pausing: There is no pause button; once started, sessions must be completed or forfeited. Stopping or interruption ends the climb (reset/fail), emphasizing commitment and preventing exploits.

### The Plateau (Success State)

- Checkpoint: Upon successfully completing the timer (hitting 0:00), the character reaches a flat "Plateau."
- Every meter climbed is added to the current elevation (how far up the hill you currently are) and lifetime elevation (how many meters you've climbed in total throughout the app)
- Rest: The user enters a "Rest" block. The character is seen sitting and resting on the flat section of the hill. The duration corresponds to how long they want their breaks to be (e.g. 5 minute break = 5 minute rest at the plateau and then back to climbing)

### The Fall (Failure State)

- Detection: The app detects if the user "backgrounds" the app (exits to home screen or switches apps) for more than 10 seconds. Turning off the phone is fine as long as they are still in the app.
- The Penalty: If the 10-second grace period is exceeded, the session is marked as failed, and the boulder rolls uncontrollably back down the hill.
- Data Consequence: The "Current Altitude" decreases by the amount they climbed for that session (e.g. getting distracted 5 minutes into a focus session loses those 5 minutes from your climb, but your lifetime elevation is kept). The user must restart the session from the previous checkpoint.

### Gamemodes:

- Normal mode: If the user fails, the boulder rolls back to the start of the current session (the last Plateau). User is at 1,000m total. They start a 25m session. They fail at minute 20. They fall back to 1,000m.
- Hardcore mode: If the user fails, the boulder rolls all the way to the bottom of the hill (0m) or a major "Basecamp" (e.g., resets the day's progress).
- Note: For the absolute MVP, we will stick to Session Reset (Standard) as the primary mechanic, but "Hardcore" can be a toggle that resets the Daily streak.

## Flow/App States

Default: user starts on the timer screen with the timer OFF (Idle).

### Idle

- Trigger: When at the plateau (after break ends or after a fall ahd you click back button) or at the very bottom (first app open or after a fall->back button on your first ever session). 
- UI: Timer shows full focus duration (e.g. 25:00). "FOCUS" label. Play affordance or "Tap to Start" on first-time.
- Animation: 
    - If at base of hill (first time), it simply shows the stickman leaning against the boulder standing still ready to push. 
    - If at plateau, after stickman walks to rest position, he's shown sitting and resting.  oulder at rest.
- Transitions out: Tap start → Climbing.

### Climbing

- Trigger: User tapped start; focus phase is active.
- UI: Countdown (e.g. 24:38). "FOCUS" label. Optional current altitude display.
- Animation: Sisyphus pushing boulder uphill; progress synced to time (e.g. 1 min = 1 m). Environment can shift with altitude. Progress markers in hill shown dynamically. Fully linear constant time animation.
- Transitions out: Reach 0:00 → Plateau. App backgrounded >10s → Fall.

### Plateau

- Trigger: Focus hit 0:00; session succeeded.
- UI: Break countdown (e.g. 5:00). "REST" or "BREAK" label.
- Animation: Character resting at plateau; boulder stationary.
- Transitions out: Break reaches 0:00 → Idle (or next Climbing).

### Fall

- Trigger: App backgrounded >10s during Climbing (and optionally during Plateau, if desired).

- Visual Sequence:
    - Detection Flash: App returns, shows frozen progress. "DISTRACTION DETECTED" flashes red.
    - Boulder Fall Animation: Stickman falters, boulder rolls rapidly out of view (downwards). Circular progress bar empties rapidly.
    - "Session Failed" Modal: a rectangular popup appears similar to in video games like Geometry Dash (without looking too much like a game)

### Reset
- Trigger: User long-presses on the screen during a Climbing session (or we could add a separate button - not decided yet)
- UI: A confirmation modal appears: "Give up on this climb? You will lose [X] meters."
     - Buttons: [Confirm] / [Cancel].
     - Action: Tapping [Confirm] triggers the same visual sequence as the Fall state. The boulder rolls down, the session fails, and the user is returned to Idle at the last checkpoint. Literally the same as Fall but its manual.
     - Animation: while the modal is live, the animation and timer pause, so its technically 'idle' but not really, its not the Idle state, the screen is just completely frozen behind (blocking modal) 
     

- Modal Content:
    - Header: "SESSION FAILED!"
    - Body: "You lost [X] meters of progress." (where X is no. of meters climbed in the current session, max possible value of X is session length)
    - A reload button that sends you back to last checkpoint and starts a new session immediately (falling -> plateau -> climbing)
    - A back button that sends you back to the last checkpoint but doesnt start a new session (falling -> plateau -> idle)
- Data Consequence: Meters climbed in total (lifetime elevation) is still kept, but the current altitude are lost.

- Transitions out: Tapping a modal button dismisses the modal and resets the UI to the last checkpoint (or Idle state).
## Data & Metrics (The Profile)

Data such as these will be tracked and displayed on your profile:

1. Current Altitude (Session): The progress made in the current active timer. This is volatile and can be lost.
2. Lifetime Elevation (Profile): The cumulative sum of all successfully banked sessions. This number never goes down (unless we implement extreme hardcore features later). This is the "High Score."
3. A heatmap showing your daily progress/meters climbed (minutes focused) just like in GitHub or Anki

## Core terminology

- Session: The current focus interval only—one climb from Start to 0:00 (success) or to Fail/Give Up. Not the entire lifetime history of the app. A new session begins when the user taps Start from Idle.
- Break: The rest period at the plateau after a successful session. The state where the user is resting and the break timer counts down; the character is at the plateau.
- Reset: User-initiated abandon (e.g. long-press "Give Up"). Same outcome as Fall (boulder rolls back, session lost) but intentional.
- Checkpoint: The last banked plateau—the altitude (meters) you had after your last successfully completed session. On Fall, you return to this point, not to zero.
- Altitude (session): How high you currently are up the hill.
- Hill: The infinite slope that you are climbing. Transcends sessions - each session contributes to the total altitude up the hill.
